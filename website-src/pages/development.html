Development

Was AI used to build this project? Yes.

That deserves a plain, honest disclosure rather than a footnote. Here is exactly what was used, and what a human decided.

Which tools were used

main coding / build agent

Freebuff

Used for repository work, implementation, build automation, testing and troubleshooting. Much of the code in this repository was written in sessions with Freebuff acting on the maintainer's direction.

prompting · planning · debugging

ChatGPT

Used for prompting, planning, troubleshooting, debugging, research assistance, and working through difficult technical problems — for example the Debian Unknown archive type failure and the Eevee resource-bundle path investigation.

direction · review · releases

Human maintainer

Directs the project, makes implementation decisions, reviews results, tests builds on a device, and decides what gets released. The maintainer also has programming knowledge and participates directly in development.

AI was used as a development tool. It is not presented as the creator of the upstream projects. AI assistance on this project does not change who wrote spoti.pw or EeveeSpotify, and nothing here should be read as claiming otherwise.

Process

How a build actually happens

  1. the build workspace is prepared with the decrypted Spotify app the build takes as input
  2. one command runs the unified pipeline: merge → resolve → inject → validate → package
  3. every validation must pass; failures stop the build — tests are never weakened to pass
  4. the maintainer installs and tests the resulting IPA on a device
  5. only then is the build added to the website's download index

Technical detail lives in the repository: docs/BUILD.md, docs/ARCHITECTURE.md, docs/UNIFICATION-AUDIT.md.

Maintainer status

This project is currently maintained by a single developer. Builds and updates are created in available free time. New IPA releases may take longer if the maintainer is busy with school, work, family, or other parts of life. There is no guaranteed release schedule.

Community continuation

If the current maintainer stops working on this project, someone else may be able to create a continuation using the available source code and the applicable upstream licenses and rights. Anyone continuing the project should preserve applicable licenses, copyright notices, attribution and upstream requirements.

This is a factual statement about continuity, not a claim of unrestricted redistribution rights — upstream licenses, including PolyForm Strict for current spoti.pw versions, remain binding on any continuation.

Limits

Honesty about what is not known

  • AI output is not assumed to be correct — the validation suite and device testing exist precisely because it sometimes is not.
  • What was verified is documented (audits, byte comparisons, load-command dumps), and so is what could not be verified.
  • Where a fact is unknown — donation links, licenses, upstream intent — the site says so instead of guessing.
  • Release metadata is read from GitHub rather than typed in, so a stale number on this site means the generator has not run, not that someone forgot to edit a page.
